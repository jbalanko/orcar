# Instructions for AI assistants working in this repo

This repo holds the LED effects for the **Orcar**: an orca art car lit by six synced Pixelblaze 3 controllers (boards A–F, firmware v3.51).

- **Writing or changing an effect?** Follow `.claude/skills/orcar-effects/SKILL.md`. If you're not Claude, read it as plain instructions. Its rulebook is `docs/ORCAR_CONTRACT.md`, and the MUSTs in it are hard requirements.
- **Changing counts, wiring, directions or the DXF?** Follow `.claude/skills/orcar-maps/SKILL.md` (and `docs/MAP_GENERATION.md`). Counts, wiring and directions are edited only in `src/template/orcar_3d_mapped.js`.
- **Never hand-edit `maps/*.json`** (including `boards.json`). They're generated by `python3 tools/mapgen.py` from the DXF in `model/` and the template; CI fails if they're stale.
- **Don't edit the template** unless you're explicitly asked to change wiring, counts or directions. Its comments are what the simulator's Reference tab shows, so keep the comment beside or above each definition accurate when you do change it.
- **Don't edit `patterns/` by hand.** It's generated by `node tools/build.mjs` from `src/`. After changing any `*.effect.js` file or the template, rebuild and commit `patterns/` too; CI fails if it's stale.
- **The simulator** (`simulator.html`, code in `sim/`) is how people see effects; `docs/SIMULATOR.md` explains it, including how to publish it as a Claude artifact. **Changing the simulator?** Read "Maintaining the simulator" in `docs/SIMULATOR.md` first (it must keep working from a file on disk with no build step, and the board code is built from function source, so it must stay self-contained). `sim/engine.js` is the emulator shared with `tools/pbsim.mjs`, so changes there affect `pbcheck` and the build too. The simulator's Docs tab shows `docs/*.md` as they are, and its editor suggestions are parsed from `docs/PIXELBLAZE_REFERENCE.md`: keep its "- `name(args)`: what it does" bullets and its tables in the same shape.
- **The public control page** (`web/play.html`, served from board A as `/play.html`) and the admin **test page** (`web/test.html`, `/test.html`) are explained in `docs/PUBLIC_UI.md`. Each is one self-contained HTML file: no build step, nothing loaded from the network (the Orcar has no internet), plain `ws://`, and nothing ever saved to the Pixelblaze's flash. Keep the code between the `web-check:pure` markers free of DOM and network calls. After changing either page, run `npm run web:check` and keep "Settings" and "The messages it uses" in `docs/PUBLIC_UI.md` accurate. Effects meant for the page follow contract §12. **Uploading to or deleting files from a board changes the live truck:** give the person the commands (`docs/PUBLIC_UI.md`, "Uploading, updating and removing the pages"), and run them yourself only when they ask you to.
- **`src/drafts/` is local work in progress** from the simulator, ignored by git and by the build. Work on a draft there if the person asks, but don't commit it; to keep one, move it to `src/effects/` (the simulator's Save to repo does the same), then build and check.
- **Finding the boards:** `tools/pbfind.py` finds every Pixelblaze on the local network (README, "Finding the boards on the network"). When someone can't reach a board, doesn't know its address, or needs to paste a pattern or upload a map, point them to it, or run it for them if you have a shell on their network. Offer to help set up the `pbfind` alias. It only lists addresses; opening each one shows which board it is.
- **The command-line tools** are described in `tools/README.md`. Read it before adding or changing a tool.
- **Keep the docs true.** When a change alters how something works, update the doc that describes it in the same change; `CONTRIBUTING.md` has a table of which doc covers what, and how to add an example, change a skill or handle a firmware update. Some docs are mirrored in the Orcar Claude project (listed in `CONTRIBUTING.md`); if you can write to that project, update its copy, otherwise tell the person which copies are now out of date.
- **Before you finish:** `npm run check` (all examples and effects) must report no `[error]`. After changing `sim/`, `web/` or the tools, run `npm run ci`.
- Project management (open questions, task lists) lives outside this repo, in the Orcar Claude project. Don't add TODO lists here.
