# Orcar map generation

The maps are generated by `tools/mapgen.py` from:
- `model/*.dxf` (the geometry),
- `src/template/orcar_3d_mapped.js` (counts, wiring order, directions),
- `maps/mapgen.json` (the name mapping, placeholder, ghost box and tolerances).

**Never hand-edit `maps/*.json`.** Read `docs/MAP_GENERATION.md` before changing anything. Paths are relative to the repo root, or to this skill's folder when it's installed on its own (copy it to a writable directory first).

## Workflow

1. **Understand the request.** Is it a new count, a direction, a wiring change or a new DXF? Count, direction and wiring changes go in the **template** only:
   - `feature(count, reversed)` for counts and directions;
   - the `BOARD_A..F` lists for wiring.

   Settings (names, placeholder, ghost box) go in `maps/mapgen.json`.
2. **Preview:** `python3 tools/mapgen.py --dry-run --compare`. Read the whole report:
   - **Errors** block writing. Fix the cause; never weaken a check to get past it.
   - **"Changes vs the previous maps"** must list only the strands you meant to change.
   - **Pitch:** a counted strand's pitch should be close to ~1.37″. "check count" means the count or the drawing is off. Tell the person.
   - Pixel 0 must be at the expected end (docs table). Rings (R1, R12–R14) start at their lowest point, heading toward starboard. That's an assumption until the strand is installed, so say so.
3. **Generate:** `python3 tools/mapgen.py`. If the ghost box changed, `--fix-template` updates the template constants. Only do that knowingly: it shifts every normalized coordinate, so every pattern must be rebuilt and re-pasted and all six maps re-uploaded.
4. **Verify:**
   - `python3 tools/mapgen.py --check` reports "up to date";
   - `npm run build && npm run check` passes;
   - preview `patterns/examples/00b-wiring-check.js` and `00-map-check.js` with `tools/pbcheck.mjs --preview` and `tools/preview.py`, then look at the images;
   - `node tools/sim-selftest.mjs` passes (the simulator reads the new maps too). Tell the person to reload `simulator.html` to see the new maps: it watches the template, not the maps.
5. **Hand back:**
   - which maps changed (the boards to re-upload; `python3 tools/pbfind.py` lists the boards' addresses; details at the top of that file);
   - whether the template changed (meaning patterns must be re-pasted);
   - the report's warnings, in plain words;
   - the on-truck checks:
     - set the matching channel length in the board's output expander settings;
     - run `00b-wiring-check` and confirm Pixel Count = Template Total = Map Pixels;
     - check each changed strand's first pixel (white) is at the expected end.

## Rules

- A strand's count must match in three places: the template, the output expander channel setting, and the map. The generator guarantees the third; the person must set the second on the controller.
- Every pixel needs a map entry (`render3D()` skips pixels past the end of a map). Unmapped strands use the placeholder; the ghosts go last.
- The DXF's even-spine labels are mirrored, so `maps/mapgen.json` swaps them. The spine-side check enforces the S1→S11 starboard-to-port convention. If it fails, fix the labels or the swap; don't disable the check.
- `ghost_box` is `"all"` (the whole sculpture). Counting strands never moves it; only DXF shape changes do, and then it's `--fix-template` plus re-pasting every pattern and uploading all six maps. Don't pin it back without asking.
